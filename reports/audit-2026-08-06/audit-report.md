## 安全与数据边界修复

- JWT 密钥缺失或短于 32 字节时启动失败；token 增加 issuer、audience、iat、exp、jti 校验。
- token 不再进入 URL、localStorage 或容器明文会话文件。
- 用户名采用 NFKC 规范化，邮箱统一小写校验，密码要求 12–128 位且包含字母和数字。
- 登录限速状态进入共享数据库，以哈希身份存储，5 次失败后阻断 5 分钟。
- 用户、组合、预警、回测 ID 使用 UUID；所有对象读写必须同时匹配 `id + user_id`。
- PostgreSQL 外键和迁移修复遗留孤儿 owner，SQLite 测试也强制开启外键。
- Webhook 只允许 HTTPS 且必须命中显式允许主机，拒绝环回、私网和重定向型 SSRF 目标。
- 通知以事件键幂等领取，记录 `pending/sent/failed`，失败可安全重试，不持久化用户正文。
- `st.html` 和 `unsafe_allow_html=True` 统一经过服务端 `nh3` 清洗；纯危险或空结果不会再触发 Streamlit 空 HTML 异常。
- 日志统一递归脱敏 token、key、cookie、headers、用户内容；生产 logger 禁止插值原始异常对象，并有 AST 回归门禁。

## 数据迁移与部署

迁移链：

1. `20260806_0001`：建立初始模式。
2. `20260806_0002`：租户外键与遗留 owner 修复。
3. `20260806_0003`：通知投递账本。
4. `20260806_0004`：共享登录限速状态。
5. `20260806_0005`：组合归档与软删除字段。

Compose 现在先等待 PostgreSQL/Redis 健康，再执行一次性迁移，迁移成功后才启动 Web/Worker/Beat。应用服务共享同一不可变版本标签；Web 使用 HTTP 健康检查，Worker 使用 Celery ping，Beat 使用调度进程探针。

备份恢复已在不映射宿主机端口、使用临时存储的全新 PostgreSQL 16 容器中演练：10 张业务/迁移表逐表行数一致，`alembic_version` 均为 `20260806_0005`，全部外键处于已验证状态且未发现孤儿数据。临时容器及临时存储在核对名称后删除，既有 `8502` 生产栈和 `ssm-remediation` 数据卷均未覆盖。

恢复性验证还覆盖了 Web/Worker 单独重启，以及 Redis 中断后的 Worker 行为：中断期间 Celery 探针正确失败，Redis 恢复后 Worker 自动重连并重新返回 `pong`。同时显式固定 `broker_connection_retry` 与 `broker_connection_retry_on_startup`，避免 Celery 6 升级时启动重连语义漂移。

并发验证结果：登录失败计数 50 路全部保留并触发封禁；同一组合 12 路并发加股全部保留；8 路同名组合创建仅 1 路成功；同一通知事件 50 路并发领取仅 1 路成功。所有探针使用临时租户/哈希身份，完成后已清理。

## 发布建议

当前修复版适合继续作为候选镜像验收，但不要直接覆盖 `8502`。推荐顺序：备份生产数据库 → 用同一镜像 digest 在预发布恢复副本 → 执行 Alembic 和 Compose smoke → 交易时段观察行情与任务 → 小流量切换 → 保留旧 digest 和数据库回滚点。
